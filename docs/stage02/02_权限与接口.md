# 权限与接口

六角色复用sys_role/sys_menu/sys_user_role/sys_role_menu，不建立第二套登录。所有企业角色无系统用户/角色管理写权限，避免借系统接口提权。后续企业授权需单独实现受限授权服务。

|角色|可查询模块|可写|

|---|---|---|

|平台管理员|企业、企业申请、员工申请、员工档案、门禁授权、业务填报、项目、任务、任务报名、任务分配、工作记录、审批轨迹|业务填报新增/草稿编辑|

|企业管理员|企业、企业申请、员工申请、员工档案、门禁授权、业务填报、项目、任务、任务报名、任务分配、工作记录、审批轨迹|业务填报新增/草稿编辑|

|企业人事专岗|员工申请、员工档案、门禁授权|无|

|企业业务岗|企业、业务填报、任务、任务报名、任务分配、项目、工作记录|业务填报新增/草稿编辑|

|企业财务岗|企业、业务填报、项目、工作记录|无|

|普通员工|员工申请、员工档案、任务、任务分配、工作记录|无|

员工只看本人申请/档案/分配/工作记录及本人已分配任务。企业管理员等管理角色按所属企业过滤；平台管理员允许全局访问。普通企业账号没有归属或所属企业停用时拒绝访问，角色叠加不会扩大到其他企业。权限取若依登录授权，归属与企业有效状态每次查数据库。

## 接口

- GET /biz/{module}/list：pageNum/pageSize（1~100）/companyId可选，返回data.rows/data.total。企业账号传别的companyId直接拒绝。

- GET /biz/{module}/{id}：权限与数据范围双重验证，跨企业与不存在统一404。

- POST /biz/daily_output：companyId（企业账号可省略）、outputDate、outputValue、unit、remark。后端固定DRAFT，创建人取登录用户。

- PUT /biz/daily_output/{id}：以上字段加version；仅DRAFT/RETURNED，版本冲突409，归属不可转移。

- 模块名称为01_schema.sql的biz_后缀固定白名单；不提供任意SQL、批量、导出、附件下载接口。

## 安全限制

Controller仅接收业务字段，Service验证若依权限与企业上下文，Mapper使用固定枚举表名及预编译参数；详情、列表、修改均有公司条件。新增不信任前端companyId。新增/修改使用若依@Log记录操作日志；审批历史由biz_audit_record预留，后续审批服务实现事务写入。

## 后续流程约束

企业信用代码唯一；申请人不得自审；驳回原因必填；审批轮次唯一；报名任务/企业唯一，重提更新同一记录并增加轮次；员工分配和上报复合外键确保同企业同用户；离职撤销有效归属；归档只读。任务报名是否公开可见由后续任务服务实现，目前员工只能查本人获分配任务。
