### 初步业务表清单

| 表名（建议） | 说明 |
| --- | --- |
| `biz_company` | 企业基本信息、状态 |
| `biz_company_apply` | 企业入驻申请及审核状态 |
| `biz_employee_apply` | 员工入驻申请及审核状态 |
| `biz_employee_info` | 员工档案与账号关联 |
| `biz_access_permission` | 门禁授权及同步状态记录 |
| `biz_daily_output` | 企业每日产值/业务填报记录 |
| `biz_task` | 平台任务或企业共享任务 |
| `biz_task_signup` | 企业任务报名及审核记录 |
| `biz_task_assignment` | 任务分配与员工领取记录 |
| `biz_project` | 项目基本信息与项目状态 |
| `biz_work_record` | 员工每日工作量记录 |
| `biz_audit_record` | 通用业务审核轨迹（可选） |

> 这是第一版设计草案；正式建表前应补充字段字典、索引、唯一性约束，以及一人多企业/多角色等关系规则。审批记录可根据实际需求分表或统一建模。

## 通用开发约束与交付要求

- **基础框架**：复用 RuoYi 用户、角色、菜单、日志、代码生成等基础能力，勿重复建设登录体系。
- **技术版本**：前端计划使用 Vue 3、Element Plus；Java/JDK、Spring Boot 等以后端 `pom.xml` 和前端 `package.json` 的实际依赖为准。
- **代码保护**：保留原考试系统，业务一体化平台使用独立项目副本或 Git 分支。
- **安全边界**：企业数据隔离、角色权限和关键业务操作，必须在后端校验，不得只依赖前端隐藏按钮。
- **数据库交付**：提交本阶段涉及的 SQL 变更脚本与字段说明；无变更则标记不适用。
- **后端交付**：提交 Controller、Service、Mapper 等涉及的代码与接口说明；无变更则标记不适用。
- **前端交付**：提交 Vue 页面、接口调用及菜单/权限配置；无变更则标记不适用。
- **测试交付**：提供正常流程、异常流程及越权场景的测试结果。
- **验收要求**：完成本文件的验收标准后，再进入下一阶段。
