交付日期：2026-10-26。本次完成本机独立验收部署，公网发布未执行。原考试代码与数据库、已有业务数据库保持独立。

- 目录：`D:/code/ruoyi-release10`，访问 `http://127.0.0.1:18081`。
- Nginx提供生产构建的静态前端，`/prod-api/`代理到127.0.0.1:18080。不是Vite开发服务器。

在PowerShell中运行以下命令。脚本不需要全局更改PowerShell执行策略：

```powershell
cd D:\code\ruoyi-release10
python tools/manage.py start
python tools/manage.py stop
```

启动器发现端口占用会停止启动，不会杀掉其他项目。停止后端时校验进程命令行确属当前目录。备份会短暂停止本站点并在完成后自动重启，适合维护窗口。

## 从干净部署包首次安装

要求：Windows、JDK17及以上（本项目Java17）、Python3.10及以上、MySQL8、Redis；Java、Python在PATH中。保持MySQL/Redis服务已运行，仅本机或受控内网访问，勿将数据库端口映射到公网。

1. 将干净ZIP解压到新的纯英文且无空格目录，例如 `D:/code/ruoyi-newsite`。不要覆盖已有验收目录。
2. 在该目录运行：

```powershell
python tools/manage.py init --database ry_platform_newsite --mysql-bin D:/mysql/bin/mysql.exe --redis-db 6 --backend-port 18082 --http-port 18083
python tools/manage.py start
```

3. 初始化时输入本机MySQL管理员密码；密码不进入命令行。数据库必须不存在，脚本拒绝复用或清空已有库。失败中断可能留下新建的半成品库，此时检查日志并改用新库名，不向原库重复导入。
4. 打开 `http://127.0.0.1:18083`，管理员用户名/随机密码保存在 `config/initial-admin.local.txt`。运行配置和随机令牌密钥保存在 `config/runtime.local.json`，文件访问范围限当前用户及SYSTEM；不要上传版本库或公开分享。
5. 正常登录后在个人中心修改初始密码，并建立自己的业务账号。干净包只有一个管理员，无演示企业或员工，公开注册默认关闭，验证码开启。平台在“系统管理→用户管理”建立申请账号并授予“普通员工”，申请账号登录后发起企业或员工入驻。企业审核通过后自动获得本企业管理员角色。

安装脚本为新库建立独立应用账号，只有本库SELECT/INSERT/UPDATE/DELETE，不使用root运行后端。后续结构迁移由管理员单独执行。初始SQL中管理员默认锁定，只有init生成随机密码后才启用。

## 安全及运行配置

部署包中的JAR已去除开发环境数据库密码及默认令牌密钥，必须通过运行配置注入。启用 `druid,release` 配置：关闭Druid控制台、Swagger与API文档，并在后端显式拒绝对应路径（包括已登录管理员），后端仅绑定127.0.0.1，禁用热重启，日志级别info；线程池64、最小4，连接池初始/最小2，最大20。Nginx关闭版本展示及管理路径，开启gzip、内容类型保护及同源框架保护，首页避免旧缓存，限制20MB请求体。

Redis生产配置应使用独立实例或独立库与访问密码；本机既有Redis服务配置未改。需要密码时初始化前设置进程环境变量 `DEPLOY_REDIS_PASSWORD`，或在本站运行配置中填写，修改后重启。多环境不可共享令牌密钥、Redis库、上传目录。退出登录和角色变更失效沿用原有实现。

公网生产切换：需准备Linux/Windows服务器、域名与有效证书；将Nginx改为TLS入口并配置防火墙，后端/MySQL/Redis仅私网访问。Windows版Nginx适用于本机验收；正式高并发部署应按服务器条件选择Linux。官方说明与下载来源： https://nginx.org/en/docs/windows.html ， https://nginx.org/en/download.html 。本次采用官网Windows 1.31.8，下载SHA256见 `deploy/stage10/nginx-source.json`，这是下载留档校验值，不是发布方签名验证。

## 数据库、上传文件和回滚

干净包提供 `sql/init.sql`（最终结构与必要菜单/角色/字典/规则、锁定管理员）和 `sql/schema-only.sql`（仅结构）。本阶段无新增业务表或字段，不需要对现有业务库重复执行初始化SQL。构建脚本依次应用第2至9阶段迁移，但明确排除所有demo.local.sql；不要用整库初始化SQL升级已有库。

```powershell
python tools/manage.py backup
python tools/manage.py restore-check D:/code/ruoyi-release10/backups/备份时间目录
```

备份同时保存SQL、uploads.zip、表行数、表内容校验值、文件SHA256。营业执照等数据库内附件随SQL以十六进制导出。restore-check仅恢复到新建 `ry_restorecheck_时间` 数据库及独立文件夹，不覆盖原库；验证全部表行数、表内容及附件哈希。操作需要输入管理员密码。备份含个人资料和密码哈希，按敏感数据保护并复制到加密的独立存储。

建议每天非业务时段备份，保留7份日备、4份周备和3份月备；每月恢复演练一次。Windows“任务计划程序→创建基本任务”可设置每日运行python，参数为本站manage.py完整路径及backup；任务须使用能读取运行配置的同一Windows用户。此策略已交付，未自动启用计划任务、异地复制或自动删除旧备份。

业务回滚时先停站点，另建数据库恢复到已验证备份，复制相同时间点上传文件，修改APP_DB_URL和DATABASE后使用新的最小权限账号并重启；不要直接覆盖正在使用的库。程序更新前备份JAR、前端、配置和数据，程序与SQL版本一起回退。原考试备份目录 `D:/code/ruoyi-exam-backup-20261023` 继续保留。

后端日志：本站logs/sys-info.log、sys-error.log、sys-user.log，按天轮转保留60天；控制台日志backend-console.log及Nginx的nginx/logs/access.log、error.log应在维护窗口停站后按月归档，监测磁盘空间。日志和备份目录不在静态根目录内。上传路径为本站uploads，不共用原业务目录。

## 构建与重新验收

后端在 `D:/code/ruoyi/RuoYi-Vue-backend` 运行 `mvn package -DskipTests`；前端在 `D:/code/ruoyi/RuoYi-Vue3` 运行 `npm.cmd run build:prod`。`-DskipTests`只是打包参数，实际业务回归由 `tests/stage10/run_regression.py` 独立执行（384项）；如仅续跑失败后的阶段可加 `--resume`。测试需源码配套的本地演示种子、凭据文件、MySQL与Redis，所有测试写入新建专用库，旧库不清空。

`deploy/stage10/build_package.py` 使用当前构建产物生成干净ZIP；先从nginx-source.json对应官网链接下载、解压到deploy/stage10/downloads.local。部署包清单manifest.json记录SHA256。升级已有站点时先备份，只替换app.jar、前端静态文件和工具，保留各自运行配置与数据；若有SQL迁移，先在备份副本演练。
