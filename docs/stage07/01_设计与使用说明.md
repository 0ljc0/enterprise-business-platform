# 第七阶段：任务发布与企业报名

## 发布范围与角色

平台管理员可创建平台任务；企业管理员/企业业务岗可创建本企业任务。用户已明确确认：企业任务仅供本企业内部使用。企业任务固定INTERNAL且容量为1家，前端无共享选项，后端拒绝伪造SHARED，数据库约束再次兜底；平台任务面向企业报名，使用SHARED。历史企业任务保持内部。

平台发布的任务可由企业报名，统一由平台审核。其他企业不能查看或报名企业发布的内部任务。仅本企业内部任务只对本企业开放，本企业承接后直接为APPROVED，符合第一阶段“内部任务无需平台审核”的规则；该内部承接记为INTERNAL_ACCEPT事件，不伪造申请人自审记录。普通员工、人事、财务无发布和报名权限。数据范围和实际角色在后端验证，不以隐藏按钮代替。

任务状态DRAFT草稿→PUBLISHED发布→CLOSED关闭招募。仅草稿可修改；发布后禁止修改标题、容量、数量、日期等字段。关闭需要原因，仅停止新增报名及待审报名的通过，不撤销已通过记录及后续执行资格。当前没有删除接口。

## 容量、截止与报名

任务必须填写标题、目标工作量、单位、报名截止、开始/结束日、企业容量。目标量正数、最多两位小数，DECIMAL(18,2)；企业容量为1~10000家，内部任务必须1家；报名截止不能晚于开始日23:59:59，结束日期不早于开始。发布时截止须晚于当前时间。时区Asia/Shanghai。

容量按审核通过企业数计算，承诺工作量另受总目标量约束。待审不占最终容量，因此待审数量可能多于可通过数量。报名时与审核通过时均检查剩余容量；审核取得任务行锁后使用锁定的当前读取得已通过报名，防止MySQL可重复读快照导致并发超额。

同企业同任务唯一。首次报名PENDING；仅待审可以WITHDRAWN取消，允许在截止后或任务关闭后撤回待审。已通过不可直接取消。REJECTED或WITHDRAWN可在任务仍开放且未截止时修改承诺量重新提交，更新同一记录、轮次增加。审核意见必填，禁止审核自己的报名、禁止重复审核。报名截止约束提交/重提，不阻止平台继续审核已收到的待审报名；但任务关闭后不能通过，只能驳回或由企业撤回。

平台通过后保留APPROVED和readyForAssignment=true，可供第八阶段员工分配使用。本阶段不伪造员工分配、执行或工作量功能。第六阶段仍仅提醒，连续漏报不阻止报名。

## 查询与信息隔离

发布管理只返回本人角色可管理的发布方任务：平台角色管理平台任务，企业角色管理本企业任务。平台不能通过本接口编辑其他企业发布的任务。可报名列表排除过期、关闭、企业容量用尽或目标工作量已满的任务。

平台任务详情向企业仅展示公开任务信息和汇总，隐藏发布账号、更新账号、关联项目ID等内部字段。未发布草稿及内部任务对其他企业不可见。

企业报名记录和审核意见仅该企业管理员/业务岗可查，其他企业无法读取、取消或修改。平台报名审核可集中查看并审核。发布企业不会因此获得其他企业完整报名或员工档案。任务和报名变更另有事件轨迹，并沿用若依操作日志。

## 接口

|方法|路径|用途|
|---|---|---|
|GET|/tasks|mine=true发布管理，否则可报名；keyword/pageNum/pageSize，最多100条|
|GET|/tasks/{id}|任务详情与容量汇总|

|POST|/tasks/signups/{id}/review|平台审核，approve/opinion/version|

## 使用

重启前后端，退出重新登录以加载新菜单。
1. s2_platform→业务平台→任务发布管理→创建平台任务，填写容量、工作量和日期，保存草稿后发布。
2. s2_a_admin或s2_a_business→可报名任务→企业报名→填写承诺工作量；在企业报名记录查看待审、取消或驳回重提。
3. s2_platform→平台报名审核→查看详情→填写通过/驳回意见。
4. 企业再次查询报名记录，通过后显示可进入待分配环节。实际分配在第八阶段实现。
5. 企业内部测试：s2_a_admin创建企业任务，范围固定本企业；本企业承接后可进入待分配，s2_b_admin无法查看或报名，无需平台重复审核。

密码沿用本地测试账号。测试SQL、并发请求及时间调整只在独立测试库执行，不向真实业务库预置发布/报名结果。本次不发送外部消息，也不推送Git远端。
