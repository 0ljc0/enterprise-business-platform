# 第四阶段：员工入驻与管理

## 业务与权限

申请使用现有若依账号，不开放匿名注册。员工选择有效企业，填写姓名、电话和岗位，保存草稿后提交。申请只能本人查看或由该企业管理员/人事查看；管理员及人事只能审核自己企业的申请。通过前不建立企业归属，企业内部数据接口拒绝访问。

DRAFT草稿→PENDING待审核→APPROVED通过/REJECTED驳回。驳回可修改原记录并重提，审批轮次递增，意见必填，禁止自审和重复审核。一个账号仅允许一份草稿或待审核申请。一次申请不能变更目标企业。

通过审核时事务内写入biz_company_user有效归属、biz_employee_info在职档案、sys_user_role员工角色、biz_audit_record审批轨迹；历史企业角色清除后仅授予普通员工，避免换企业继承旧权限。已有有效企业归属不能再次入驻。角色变化在事务提交后清除该用户已有登录会话，需重新登录。企业归属仍在每次访问时校验。

员工只能修改本人业务档案的姓名和联系电话，不能修改工号、岗位、企业、账号或状态；不修改sys_user登录名、密码、全局昵称。企业管理员/人事可维护本企业员工姓名、电话、岗位、工号，企业管理员及平台管理员档案仅允许本人维护。

仅企业管理员可授予普通员工、企业人事、企业业务、企业财务四类业务角色；不能授予平台管理员、企业管理员，不能给自己或管理员账号调整角色。授权操作替换以上业务角色并始终保留普通员工。角色权限按若依菜单计算，人事不能授予角色。

## 数据库迁移

sql/stage04/01_employee.sql仅执行一次：
- biz_employee_apply新增real_name VARCHAR(50)、contact_phone VARCHAR(30)。
- 替换uk_apply_active为uk_active_employee_applicant(active_user)，限制一账号一份有效申请，不再仅限制同企业。
- biz_employee_info新增contact_phone VARCHAR(30)。
- 菜单6600员工入驻、6601员工审核、6602员工管理、6603我的员工资料；按钮6604分配业务角色。
- 权限biz:employee:apply/profile分配给已有六类角色；review/manage仅企业管理员和企业人事；roles仅企业管理员。平台管理员通过既有系统管理能力管理账号，本阶段不提供跨企业员工审批旁路。
- 演示账号在02_demo.local.sql，本地使用，不纳入版本库。当前业务库在迁移前备份为工作区backups/ry_platform_before_stage04.sql。

## 接口

|方法|路径|用途|
|---|---|---|
|GET|/employees/companies|可入驻企业，仅返回ID和名称，最多500条|
|GET|/employees/applications|本人申请；review=true为本企业审批列表，最多200条|
|GET|/employees/applications/{id}|详情与历轮审核意见|
|POST|/employees/applications|草稿创建|
|PUT|/employees/applications/{id}|本人修改草稿/驳回申请|
|POST|/employees/applications/{id}/submit|提交或重提|
|POST|/employees/applications/{id}/review|本企业审核，approve/opinion|
|GET|/employees/staff|本企业员工列表，最多200条|
|GET|/employees/staff/{id}|本企业员工详情|
|PUT|/employees/staff/{id}|本企业档案维护|
|GET|/employees/me|本人在职档案|
|PUT|/employees/me/{id}|本人允许字段修改|
|PUT|/employees/staff/{id}/roles|受限角色分配，JSON字符串数组|

申请输入companyId、realName、contactPhone、jobTitle；更新加version。管理档案加employeeNo。后端固定账号和状态，忽略前端伪造的企业/账号/角色字段。工号企业内唯一，更新采用version乐观锁。创建、修改、提交、审核、资料修改、授权均使用若依操作日志。

## 使用步骤

1. 按原方法重启前后端。申请员工使用s4_applicant登录，进入业务平台→员工入驻→申请加入企业，选择演示企业A，填写并保存后提交。密码与第二阶段本地测试密码相同（创建时复制s2_a_employee密码）。
2. 使用s2_a_admin或s2_a_hr登录，进入员工审核，查看详情，通过或填写意见驳回。
3. 通过后员工重新登录，在我的员工资料查看并修改允许字段。
4. 管理员在员工管理查看/修改本企业员工，或分配业务角色。角色对话框是替换操作，请选择所有需要保留的业务角色；普通员工始终保留。保存后目标员工需要重新登录。
5. 可用s2_b_admin验证无法读取、审核或修改A企业员工。

s4_other为另一未归属企业的本地演示账号。真实业务库不预置审批结果。s2_unbound在第三阶段人工验收后可能已经是企业管理员，不再作为第四阶段未入驻演示账号。

## 边界

本阶段实现员工入驻、查询、资料维护及受限角色分配。员工状态为ACTIVE/LEFT，当前提供查询，不开放离职、转企业或删除接口。正式离职流程应同时撤销企业归属、业务角色、门禁及未完任务，不能仅改前端状态。门禁同步与任务管理留待对应阶段。未执行浏览器逐页人工验收，接口验收见测试报告。
